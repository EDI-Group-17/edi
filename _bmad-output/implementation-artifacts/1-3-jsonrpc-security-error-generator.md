# Story 1.3: Centralized JSON-RPC Security Error Framework

## Story Statement
**As a** JSON-RPC Client / AI SDK,  
**I want to** receive strictly compliant JSON-RPC 2.0 error frames when AgentShield blocks, rate limits, or rejects a request,  
**So that** my calling application can programmaticly intercept, parse, and handle different security failure modes cleanly.

---

## Acceptance Criteria (BDD)

### Scenario 1: strict JSON-RPC 2.0 Compliance [COMPLETED]
- **Given** any gateway intercept action (HITL deny, block, rate limit)
- **When** the proxy returns the error response
- **Then** the JSON payload contains `jsonrpc: "2.0"`
- **And** the request `id` matches the input payload `id` exactly (or `null` if the request id is unparseable)
- **And** the `error` object contains numeric `code`, string `message`, and structured `data`.

### Scenario 2: Standardized Security Error Codes [COMPLETED]
- **Given** different block triggers
- **When** the response is generated by `src/gateway/errors.py`
- **Then** the numeric codes are mapped exactly:
  - `-32001`: HITL_ACTION_DENIED
  - `-32002`: INJECTION_INTERCEPTED
  - `-32003`: RATE_LIMIT_EXCEEDED
  - `-32004`: LOOP_QUARANTINED
  - `-32603`: TARGET_CONNECTION_FAILURE
